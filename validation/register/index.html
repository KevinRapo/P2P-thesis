    Issue register: the original MARLEM implementation¶

    Every issue found in the public MARLEM release and in the two papers that describe it, in one list with one stable ID each. This is the register the thesis cites. It describes the original, frozen at the commit below; what the rebuild does about each issue is on the detail pages (market layer, RL layer), not here.

    Version 1.0, 14 October 2026. A new finding gets the next free ID; existing IDs and their descriptions do not change.

    About this register¶

    What was audited.

    • The code: the authors' repository salazarna/marlem at commit 15d6715 (March 2026), the public release both papers point to. Every code link below is pinned to that commit, so its line numbers stay valid.
    • [P1] Salazar-Peña, Tabares, González-Mancera. MARLEM: A multi-agent reinforcement learning simulation framework for implicit cooperation in decentralized local energy markets. Applied Energy 412 (2026) 127546, doi:10.1016/j.apenergy.2026.127546. Peer reviewed. Defines the market, the agents, the grid and the training paradigms; its case studies use zero-intelligence agents.
    • [P2] Same authors. Harnessing implicit cooperation: a multi-agent reinforcement learning approach towards decentralized local energy markets. SSRN preprint 6685504, not peer reviewed. Gives the paradigms' and algorithms' formulas and trains the 3 × 3 matrix of paradigms and algorithms.
    • RLlib (Ray 2.51.1), where the original relies on its behaviour; checked in its installed source.

    How the issues were found: an AI-assisted audit. The code was reviewed line by line against the two papers with the help of an AI coding assistant, which proposed candidate findings together with the lines at fault. No candidate entered the register on the assistant's word. Each was checked by the author against the original code: by reading the cited lines and the code that calls them, by a small executable demonstration on the original code, by a test on the RL test bench, or by running the original as shipped. The Evidence column says which. Findings about the papers' method itself (origin Paper) are judgments that no test can settle; they are listed because the rebuild has to decide them.

    What an issue is. A defect in the code, a deviation of the code from the papers, or a question the papers leave open. It is not necessarily a bug, and the number of issues is not a measure of the papers' ideas: most of the method holds up (see Problems in the papers' method). Which implementation produced the papers' published results is not known; this register describes the public release only.

    Six issues decide most of what the original can and cannot show:

    • Batteries run backwards (I-18, I-20): selling charges the battery.
    • Two pricing mechanisms return the buyer's bid (I-13, I-17), one of them the mechanism of [P1]'s own case study.
    • No money moves (I-27, I-28, I-24): profit, fees and the DSO balance stay at zero.
    • The grid is not a power flow (I-70, I-57, I-33): linear estimates on a disconnected graph whose flows pile up over the day.
    • The reward the agents learn from is partly constant (I-43, I-44, I-41).
    • CTDE never trains the networks that act (I-48), and the paradigms are not compared like for like (R-03, I-60, I-73).

    Problems in the papers' method¶

    Whether the papers' method holds up on its own terms, whatever the code does. None of these prevents building a working model; each needs a recorded decision, because the papers cannot settle it.

    Topic The problem Issues
    Reward form [P1] eq. 4 as printed reduces to \(R_{\text{base}}\) for normalised factors; [P2] eq. 3 has a different form, and the code a third. The papers' central contribution, the cooperation bonus, has no single definition I-42
    Reward components The parts of \(R_{\text{base}}\) are given only as names, weights and ranges; the code is the only specification, and it is partly broken I-76, I-43, I-44
    Cooperation factor Claimed to lie in [0, 1], but welfare, liquidity, spread and volatility have no stated normalisation I-75, I-41
    Social welfare (eq. 21) Defined as consumer plus producer surplus but written as \(\sum p\,q\), which is turnover I-36
    Imbalance (eq. 24) Over trades it is 0 by construction (every trade has a buyer and a seller); it only means something over orders or physical positions. \(B_{\text{grid}}\) after DSO clearing is 0 for the same reason, so its timing matters I-68, I-35, I-23
    KPI labels "DER self-consumption" is defined as the peer-to-peer share I-69
    Grid physics Losses linear in \(d\,q\) and unbounded, voltage drop \(f\,d\), flows as transport on a graph; called "high-fidelity" I-70
    Grid fees (eq. 8) \(F_{\text{trans}}\) has no formula; no fee factor has a value; the thermal threshold sits below the congestion threshold; the same-zone bonus outweighs every fee I-29, I-30, I-74, N-05
    Battery (eq. 15–16) No charge or discharge power limit, although the text claims one; eq. 15 ignores efficiency I-71
    Market design A DSO-preferred sub-stage the paper does not describe; a clearing price that mixes peer prices with the DSO's tariffs; a pricing mechanism used in the case study that §3.3.3 does not list I-15, I-16, I-17
    Reputation (eq. 12) Weights and decay have no values; fairness and grid contribution have no formulas I-38a, I-38b, I-38c
    Actions No explicit "submit nothing"; order side and partner are discrete but modelled as continuous numbers I-11, I-10
    Information Forecasts with 30 % error are specified, but the observation exposes the exact remaining future demand I-39
    Units USD/MWh in [P1]'s case study, up to 600 "USD/kWh" in [P2]; kWh per implicit 1-hour step I-56
    Paradigms CTCE is called a theoretical upper bound but is trained by the same approximate learner; [P2] eq. 18 gives CTDE a joint-action critic, which PPO and APPO do not have I-60, I-48
    Comparison One "mean episode reward" across paradigms whose objectives are a group sum and per-agent returns; the paradigms use different networks I-73, R-03
    Evaluation One fixed seed, evaluation on the training scenario, ranking by the shaped reward; the budget is given in episodes but counted in iterations; \(B_{\text{index}}\) is undefined I-72, I-50, I-80
    Data The case-study profile-to-agent mapping and scaling are not published I-51

    The weak points are definitions, not the architecture: a market with a physical grid layer, KPI-shaped observations and rewards, and three training paradigms compared is a coherent design worth building on.

    What this means for the published results¶

    The papers' figures cannot be traced to a specific version of the code. If they were produced with the public release:

    • [P1], Case 5 (batteries, zero-intelligence agents). The case uses the bid-ask spread mechanism, which returns the buyer's bid (I-17), so the peer-to-peer prices of Fig. 5 are buyer bids. Selling charged the batteries (I-18), discharge drained less than it delivered (I-20), and a charge reaching the upper limit was refused entirely (I-19). No money moved (I-27, I-28, I-24). The "imbalance" and "coordination score" of Figs. 6–7 measure traded volume (I-35, I-68). The conclusion that batteries stabilise prices is not supported by this code.
    • [P2], the 3 × 3 MARL experiment. The reward the agents optimised has constant or inactive parts (I-43, I-44), an unnormalised cooperation factor (I-41) and no terminal penalty (I-02); the observation exposes exact future demand (I-39) and a profit that is always 0 (I-27). Every CTDE result comes from untrained policies (I-48); the grouped SAC actors never learned from their critics (R-05); CTCE and CTDE trials may have run with NaN losses (R-01, R-02, I-49); APPO's λ search changed nothing (R-06); and the ranking mixes paradigm with network and training length on one seed (R-03, I-60, I-72). [P2]'s conclusions about CTDE are not supported by this code.

    A thesis built on the rebuild is therefore a corrected reimplementation of the framework the papers describe, not a reproduction of their results.

    Limits of this audit¶

    • src/analytics/ (the analytics package) and src/visualization/ were not audited line by line; I-65 is a judgment on the analytics as a whole.
    • Of the notebooks, only the Case 5 and Case 6 setups and the two examples were checked.
    • Read issues rest on code reading; the RL page lists the tests that would confirm its Read issues (rl.md, Not tested yet).
    • The 48 demonstrations behind the Demo evidence were written on an earlier branch of this repository and are not yet part of this one.
